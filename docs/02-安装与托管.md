# 02 · 安装与托管

形态已经定了（[01](01-开工前：先测什么.md)），开始装。用 sing-box 单进程承载全部入站——比同时跑 Xray + hysteria 省一个进程、省内存，容器机尤其重要。

## 输入

- 步骤 01 的形态结论
- 目标机 root 权限
- 一个可用的外部端口（TCP 和/或 UDP）
- 若要上 CF 隧道：一个自己的域名 + CF 账号（可选）

## 主路径：一条命令

```bash
# 在工作机仓根目录
./skills/new-proxy-node/scripts/install-singbox-node.sh \
  --host <IP> --ssh-port <SSH_PORT> \
  --name <name> \
  --mode dual \
  --tcp-port <TCP_PORT> --udp-port <UDP_PORT> \
  --domain www.apple.com \
  --nodes-root <nodes-root>
```

`--mode`：`dual`（Reality + hy2）/ `reality`（只 TCP）/ `hy2`（只 UDP）/ `triple`（再加 CF WS 入站）。
`--dry-run` 只打印将要执行的步骤，先跑一次看它打算干什么。`--force` 才覆盖已有配置。

它做的事：下载校验二进制 → 流式传到目标机 → 生成凭据（UUID / Reality 密钥对 / short_id / hy2 自签证书）→ 渲染配置 → `sing-box check` → 装服务并启动 → 起本地 SOCKS 做自检 → 写 `<nodes-root>/<name>/node-info.md`(600) 与 `client-test.json`。

下面是它每一步的**手工等价动作**——出问题时按这个拆开看，或者想自己控制细节时照着做。

## 步骤 1 · 二进制（本地下载，只传结果）

容器机磁盘小、`curl` 可能不通 GitHub，所以**在工作机下载并校验**，只把二进制流过去。

```bash
V=1.14.4
cd $(mktemp -d)
# glibc 用这个；Alpine / 其他 musl 用 -musl 变体
curl -fLO https://github.com/SagerNet/sing-box/releases/download/v$V/sing-box-$V-linux-amd64.tar.gz
curl -fLO https://github.com/SagerNet/sing-box/releases/download/v$V/sing-box-$V-linux-amd64.tar.gz.sha256sum
sha256sum -c sing-box-$V-linux-amd64.tar.gz.sha256sum
tar xzf sing-box-$V-linux-amd64.tar.gz
# 流式传送，不在目标机留 tar 包
ssh -p <SSH_PORT> root@<IP> 'cat > /usr/local/bin/sing-box && chmod 755 /usr/local/bin/sing-box' \
  < sing-box-$V-linux-amd64/sing-box
# 双向 sha 对账
sha256sum sing-box-$V-linux-amd64/sing-box
ssh -p <SSH_PORT> root@<IP> 'sha256sum /usr/local/bin/sing-box'
ssh -p <SSH_PORT> root@<IP> '/usr/local/bin/sing-box version'
```

判据：两侧 sha 完全一致，且 `version` 能打印。**sha 不一致就停**——多半是流被截断。

## 步骤 2 · 凭据

```bash
UUID=$(cat /proc/sys/kernel/random/uuid)
set -- $(sing-box generate reality-keypair 2>/dev/null | tr -d '\n' | sed 's/PrivateKey:/\n/;s/PublicKey:/\n/' | tr -s ' \n' ' ')
# 或直接：sing-box generate reality-keypair  →  PrivateKey: xxx / PublicKey: yyy
SHORT_ID=$(sing-box generate rand --hex 8)
HY2_PASS=$(sing-box generate rand --base64 16)
HY2_OBFS=$(sing-box generate rand --base64 16)
```

hy2 自签证书（一年期，容器机够用）：

```bash
openssl ecparam -genkey -name prime256v1 -out /etc/sing-box/hy2.key
openssl req -new -x509 -days 365 -key /etc/sing-box/hy2.key \
  -out /etc/sing-box/hy2.crt -subj "/CN=<name>"
chmod 600 /etc/sing-box/hy2.key
```

**私钥纪律**：Reality 的 `private_key` 与 hy2 私钥只留在目标机配置里（600），交付文件只写 UUID / 公钥 / short_id / 口令 / obfs。写进聊天、文档、报告的都算泄漏。

## 步骤 3 · 配置

模板：`skills/new-proxy-node/templates/singbox-server.json`，替换占位符即可（`{{UUID}}` `{{PRIVATE_KEY}}` `{{SHORT_ID}}` `{{HY2_PASS}}` `{{OBFS_PASS}}` `{{WS_PATH}}` `{{TCP_PORT}}` `{{UDP_PORT}}` `{{SNI}}`）。

按形态删掉不用的入站块，然后**必须**校验：

```bash
scp -P <SSH_PORT> config.json root@<IP>:/etc/sing-box/config.json
ssh -p <SSH_PORT> root@<IP> 'chmod 600 /etc/sing-box/config.json && /usr/local/bin/sing-box check -c /etc/sing-box/config.json && echo OK'
```

`check` 不过就不要往下走。常见原因：JSON 尾逗号、端口与已有服务冲突、`reality` 块缺 `short_id`。

共享母鸡的 hy2 加固（**必做**，否则客户端 Brutal 会把母鸡吃掉）：

```json
"ignore_client_bandwidth": true,
"obfs": { "type": "salamander", "password": "<OBFS_PASS>" }
```

客户端侧对应**不填** up/down。

## 步骤 4 · 托管（重启/崩溃自愈）

Alpine / OpenRC：

```bash
cat > /etc/init.d/sing-box <<'EOF'
#!/sbin/openrc-run
name="sing-box"
command="/usr/local/bin/sing-box"
command_args="run -c /etc/sing-box/config.json"
command_background=true
pidfile="/run/${RC_SVCNAME}.pid"
supervise_daemon_args="--respawn-delay 5 --respawn-max 0"
depend() { need net; after firewall; }
EOF
chmod 755 /etc/init.d/sing-box
rc-update add sing-box default && rc-service sing-box start && rc-service sing-box status
```

systemd：

```ini
[Unit]
Description=sing-box
After=network-online.target
[Service]
ExecStart=/usr/local/bin/sing-box run -c /etc/sing-box/config.json
Restart=always
RestartSec=5
LimitNOFILE=65535
[Install]
WantedBy=multi-user.target
```

**自愈要实测**，不能只看 `Restart=always`：

```bash
pkill -9 sing-box; sleep 6; pgrep -a sing-box   # 6 秒后重新在跑 = 自愈成立
```

## 步骤 5 · 服务端自检

```bash
ss -lntup | grep -E '<TCP_PORT>|<UDP_PORT>'   # 端口在听
tail -n 30 /var/log/sing-box.log              # 无 panic / permission denied
```

再从工作机打一次（外部视角，绕代理）：

```bash
curl -sv --noproxy '*' --max-time 8 http://<IP>:<TCP_PORT>/ -o /dev/null 2>&1 | grep -E 'Connected|timed out'
```

## 步骤 6 · 内存纪律（小容器必读）

1C / 128M 的容器里，**cgroup 统计口径**和 `free` 不一样：

```bash
cat /sys/fs/cgroup/memory.max
grep -E '^(anon|file) ' /sys/fs/cgroup/memory.stat
```

`anon` 是进程真正占的；`file` 是 page cache，可被回收但**会计入 cgroup**，写文件多时能把限额顶满，然后内核开始 OOM-kill（表现为进程莫名消失、`ss` 连不上）。

手动回收（只回收文件缓存，不动 anon）：

```bash
echo 10M > /sys/fs/cgroup/memory.reclaim   # 一次 10M，按需重复 3–5 次
```

长期方案：`skills/new-proxy-node/templates/mem-reclaim.sh` + `mem-reclaim.openrc`，每 15 分钟检查一次，用量 >60% 才回收，单次最多 30M 并留 20M 余量。装法：

```bash
scp .../mem-reclaim.sh root@<IP>:/usr/local/bin/ && chmod 755 /usr/local/bin/mem-reclaim.sh
scp .../mem-reclaim.openrc root@<IP>:/etc/init.d/mem-reclaim && chmod 755 /etc/init.d/mem-reclaim
ssh -p <SSH_PORT> root@<IP> 'rc-update add mem-reclaim default && rc-service mem-reclaim start'
```

> 压测教训：1C/1G 的机器上 30Mbps hy2 压测后容器用户态全崩（OOM 或磁盘满）。低价 NAT 机是**轻量自用**定位，别在上面跑长连接大流量。
