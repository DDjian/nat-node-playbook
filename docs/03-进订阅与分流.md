# 03 · 进订阅与分流

服务端通了（[02](02-安装与托管.md)），现在让手机、PC、路由器都能用它，并且知道什么流量走它。

只有一个节点时，直接拿 `client-test.json` 就是客户端配置，可以完全跳过本章。有多台机器、或多台设备要同步，才需要订阅。

## 输入

| 项 | 说明 |
|---|---|
| 节点参数 | 从 `node-info.md` 抄，**不要**从聊天记录里找 |
| 一台订阅生成机 | 任意小机器，只发静态文件，不过流量 |
| 域名（可选） | 没有就直连 IP，但会被指纹 |
| 令牌 | 每条档位一个，独立可吊销 |

## 架构

```
/opt/sub-gen/                    生成器（唯一源头）
├── template.yaml                规则 / DNS / 组结构（可公开的部分）
├── nodes.private.yaml           节点清单（含口令，600）
├── sub.conf                     档位定义：<名>:<令牌>:<排除前缀>
└── gen.py                       渲染 + 结构自检 + mihomo -t + 原子发布
        │  发布
        ▼
/srv/sub/<令牌>/sub.yaml         静态文件，由 Caddy/nginx 以 https 提供
        │  客户端拉取（只拉配置，流量直连节点）
        ▼
路由器 / 手机 / PC
```

要点：**永远不要手改已发布的 `sub.yaml`**。下次生成会被覆盖，而且三层就对不上了。

## 生成与发布

```bash
ssh <subhost> 'vi /opt/sub-gen/template.yaml'          # 改规则
ssh <subhost> 'vi /opt/sub-gen/nodes.private.yaml'     # 加/改节点
ssh <subhost> 'python3 /opt/sub-gen/gen.py'
```

`gen.py` 必须做三件事，缺一件就会把坏配置发给所有客户端：

1. **结构自检**：组里引用的节点必须存在（引用了不存在的节点直接整批不发布——这是好事，别绕过）；
2. **`mihomo -t` 校验**：内核自己能不能吃下这份配置；
3. **原子发布**：内容无变化就跳过；有变化先写临时文件再 `rename`，不出现半截文件。

## 三层一致（交付判据）

```bash
# 生成物
ssh <subhost> 'sha256sum /srv/sub/<令牌>/sub.yaml'
# 分发文件（线上）
curl -s -A 'clash.meta/1.19.30' 'https://<域名>/<令牌>/sub.yaml' | sha256sum
# 客户端实际生效：客户端里点更新 → 看节点列表与规则条数
```

三者一致才算发布成功。演练时最常出的问题：CDN/反代缓存旧文件（拉到的 sha 与服务器不同 → 加 `Cache-Control: no-store` 或换文件名带版本）。

## 必须有的一条直连规则

新节点的 IP 要加进订阅的直连段，否则**家宽本机自测会假失败**：

```yaml
rules:
  - IP-CIDR,<节点IP>/32,DIRECT,no-resolve
```

原因：客户端开着代理去连节点本身，请求会被自己的规则再送进代理，形成「代理连代理」，表现为延迟正常但握手超时。

**例外**：TCP 全封、只放 UDP 的机器**不要**加。它的 IP 加了直连会让客户端以为「这个 IP 直连可达」，而实际 TCP 不通，反而搞乱自愈逻辑；更糟的是如果 SSH 也走同一 IP，会把自己锁死。

## 分组设计

| 组 | 类型 | 成员 | 用途 |
|---|---|---|---|
| `Proxy` | select | 手动 + 全部节点 | 普通境外流量 |
| `Proxy-Auto` | url-test | 全部形态 | 自动挑最低延迟 |
| `AI` | select | **显式名单** | AI 服务，钉在固定出口（换 IP 会掉登录态） |
| `YouTube` | select | 手动 + 非 `-cf` 形态 | 视频 |
| `YouTube-Auto` | url-test | 非 `-cf`、非低带宽 | 自动挑 |
| `DIRECT` / `REJECT` | 内置 | — | — |

`AI` 用显式名单而不是自动：自动组会在两个出口之间来回切，AI 服务看到 IP 变化就登出。

模板里的 `{{PROXY_AUTO_MEMBERS}}` / `{{YOUTUBE_AUTO_MEMBERS}}` / `{{NODE_MEMBERS}}` 由 `gen.py` 从 `nodes.private.yaml` 渲染，**不要手改组成员**——下次生成就没了。

## 节点标记（写在节点块上方的一行注释）

| 标记 | 效果 | 典型用法 |
|---|---|---|
| `# park: 原因` | 整条不渲染（proxies 与所有组都没有） | 机器到期、暂时下线 |
| `# dead` | 仍下发，但摘出所有自动组 | 能连但不稳定，留着手动启用 |
| `# low-bw: 10M` | 摘出 `YouTube` 系列组 | 带宽跑不动 4K |
| `# quota: JP 300G/月` | 客户端可见名加后缀 | 提醒自己这台有月流量上限 |

`# park` 优于删块：删了要回滚就得手工重写，park 只需删一行注释。

## 加一台节点（四步）

1. 往 `nodes.private.yaml` 追加条目，**每种形态独立命名**：`<name>` / `<name>-hy2` / `<name>-cf`；
2. `python3 /opt/sub-gen/gen.py`（组员自动带上，不用手改）；
3. 客户端刷新订阅，`/proxies` 里确认新条目在列，实测延迟；
4. 更新台账与变更记录（含备份与回滚）。

## 命名是跨系统契约

改一个节点名要连带改四处，漏一处就是静默失效：

1. `nodes.private.yaml` 的 `- name:` → 重新生成；
2. 路由器订阅文件 + 运行态文件（两份都要，否则重启带回旧名）；
3. 路由器上任何**硬编码节点名**的脚本（兜底切换脚本、白名单）→ 改成按前缀动态发现；
4. 对外档位的 `AI` 名单。
