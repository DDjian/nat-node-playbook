# 99 · 交付清单与模板

一台机器上架完，目录里应该有这五样东西。缺一样，三个月后的自己就得靠猜。

```
<nodes-root>/<name>/
├── BRIEF.md            任务书：为什么上、约束是什么、选中哪种形态
├── node-info.md        连接参数与凭据（权限 600）
├── client-test.json    客户端冒烟配置（权限 600）
├── cc-final.md         验收报告：证据与已知限制
└── ip-quality.txt      体检原始输出
```

```markdown

## 机器
- 平台 / 机位：<平台> <机房>
- 规格：<C> 核 / <MEM>MB / <DISK>GB / 月流量 <Q>
- 到期：<日期>
- 入站：TCP <端口列表> / UDP <端口列表>

## 形态决策（依据来自 01 的实测）
| 项 | 实测结果 | 命令 |
|---|---|---|
| 大陆侧 TCP | 通 / 不通 | `curl -sv --noproxy '*' http://<IP>:<PORT>/` |
| 入站 UDP | 通 / 不通（InDatagrams +N） | `udp-check.sh <IP> <PORT> 5 <sender>` |

结论：**<双协议 / 单协议 Reality / 单协议 hy2 / 退货>**
理由：<一句话>

## 约束
- 是否加直连规则：<是/否>，理由：<家宽可否直连>
- IP 质量预判：<机房 IP / 风险分 / 适合干什么>
- 特别限制：<平台条款、端口数量、禁止项>

## 步骤
按 `docs/02` → `docs/03` → `docs/04` 执行，逐步勾 `docs/99` 的清单。
```

## client-test.json

最小可用客户端配置：一个 socks 入站（`127.0.0.1:20888`）+ 一个指向本节点的出站。用于 [04 第 3 步](04-验证：怎么算通.md) 的外部 vantage 验证，也方便没有图形客户端的机器排障。

```json
{
  "log": { "level": "warn" },
  "inbounds": [{ "type": "socks", "listen": "127.0.0.1", "listen_port": 20888 }],
  "outbounds": [{ "type": "vless", "tag": "node", "server": "<IP>", "server_port": 443,
    "uuid": "<uuid>", "flow": "xtls-rprx-vision",
    "tls": { "enabled": true, "server_name": "<SNI>",
      "reality": { "enabled": true, "public_key": "<pub>", "short_id": "<hex>" } } }]
}
```

## 提交前：脱敏扫描

```bash
./scripts/redact-scan.sh                # 扫工作区，列出疑似敏感内容
./scripts/redact-scan.sh --staged       # 只扫 git 暂存区（pre-commit 用）
```

规则覆盖：IPv4/IPv6 字面量、订阅令牌形态、UUID、base64 私钥块、真实域名、节点目录名。命中即拦。

装进 git hook：

```bash
git config core.hooksPath .githooks
```
