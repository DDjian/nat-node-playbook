# 01 · 开工前：先测什么

拿到一台新机器，**装任何东西之前**先把下面四件事测完。这一步花 15 分钟，决定后面几小时是「上架」还是「退货」。

## 输入

| 项 | 从哪来 | 备注 |
|---|---|---|
| IP / 主机名 | 平台面板 | NAT 机通常是共享 IP + 端口映射 |
| SSH 端口 | 面板的端口映射表 | 常常不是 22，别默认 22 |
| SSH 口令或密钥 | 平台邮件 / 面板 | 首次登录建议改口令、装自己的公钥 |
| 端口映射表 | 面板 | 有几个可用 TCP 端口、几个 UDP 端口 |
| 流量与带宽限额 | 面板 | 决定能不能跑大流量、能不能上 4K |
| 退款条款 | 平台 TOS / 订单页 | **几天内可退**，这是整章的时间约束 |

> NAT 平台的常见条款：禁止当公共代理/机场、禁止长期占满带宽、禁止扫描外网。低价机按**轻量自用**设计，别拿它做共享出口。

## 步骤 1 · 能不能登进去

```bash
ssh -p <SSH_PORT> -o ConnectTimeout=10 root@<IP>
```

进不去先分辨两种情况：

- `Connection refused` → 端口不对或服务没起，回面板核对映射；
- `Connection timed out` → 入口被封或 IP 被换，**这是危险信号**，先别装东西。

## 步骤 2 · 机器底子（只读，30 秒）

拷 `skills/new-proxy-node/scripts/node-preflight.sh` 上去跑一遍：

```bash
scp -P <SSH_PORT> skills/new-proxy-node/scripts/node-preflight.sh root@<IP>:/tmp/
ssh -p <SSH_PORT> root@<IP> 'sh /tmp/node-preflight.sh'
```

它只打印事实，不改任何东西：发行版 / libc（**Alpine 是 musl，装错二进制会直接跑不起来**）、init 系统（OpenRC 还是 systemd）、cgroup 内存上限、已监听端口、有没有旧协议残留、出站是否通。

**必须记住的两个数**：内存上限、磁盘余量。128M / 192M 的容器是常态，后面每一步都要按这个约束来。

## 步骤 3 · TCP 通不通（必须从外面打回来）

目标机上先起一个临时监听，别用正式服务，避免测试污染：

```bash
# 目标机
python3 -m http.server <TCP_PORT> --bind 0.0.0.0
```

工作机（`<sender>`）上**绕开一切代理**去连：

```bash
curl -sv --noproxy '*' --max-time 8 http://<IP>:<TCP_PORT>/ -o /dev/null
```

判读：

| 输出 | 含义 |
|---|---|
| `Connected to <IP>` + HTTP 200/404 | **TCP 通** |
| `Connection refused` | 端口映射没生效，或服务没在听 → 先修映射 |
| `Connection timed out` / `Operation timed out` | 大陆侧到该端口被墙 / 平台未放行 → **TCP 不通** |

⚠️ 三个会骗人的东西：

- **透明代理**：工作机若挂着透明代理，`nc -z` 对**任意**境外 IP:端口都报 OPEN（本地代理先握手）。所以必须 `--noproxy '*'`，且先 `curl -s https://icanhazip.com` 确认自己的出口是本地。
- **ICMP**：`ping` 通 ≠ 端口通。ICMP 和 TCP 是两条独立的路由/策略。
- **面板的「已放行」标记**：面板说放行不代表上层链路放行。只认从外面打通。

测完记得杀掉临时监听（`Ctrl-C`）。

## 步骤 4 · UDP 通不通（单独测，别和 TCP 合并判断）

UDP 无法靠握手判断，只能用**计数**：目标机上看内核收到的 UDP 数据报数，外面发 N 个，精确 +N 才算通。

```bash
# 目标机：先记基线，再起监听
awk '/^Udp:/{print "InDatagrams",$2}' /proc/net/snmp
nc -u -l -p <UDP_PORT>       # BusyBox/Alpine 用 nc -u -l -p；有 ncat 时用 ncat -u -l <UDP_PORT>
```

工作机发 5 个包（脚本做完了这一套）：

```bash
skills/new-proxy-node/scripts/udp-check.sh <目标机IP> <UDP_PORT> 5 <sender>
```

脚本判据：`InDatagrams` 精确 +5 → **UDP 通**；+0 或只 +1 → 不通。**必须 ≥2 发**，单发可能是 ICMP 或重复计数。

再对外发一次（从公网视角，绕过自己的工作机）：

```bash
# 任意第三方 vantage；或用另一台云主机
ncat -u --send-only -w 1 <IP> <UDP_PORT> </dev/zero
```

## 步骤 5 · 定形态

| TCP | UDP | 形态 | 装什么 | 加直连规则？ |
|---|---|---|---|---|
| 通 | 通 | 双协议（推荐） | sing-box 单进程：Reality + hysteria2 | 加（家宽能直连它） |
| 通 | 不通 | 单协议 | 只留 Reality（或 VLESS-WS） | 加 |
| 不通 | 通 | 单协议（别退） | 只留 hysteria2；Reality 删掉 | **不加**（加了自断 SSH） |
| 不通 | 不通 | — | 不装 | 走退货 |

判据来源只能是步骤 3 / 4 的实测输出，不是面板描述，也不是「同机房别的机器能通」。

## 步骤 6 · 退货（该退就退，别硬上）

**先卡时间**：多数平台退款窗口 24–72 小时，从付款算。所以测试要在拿到机器后第一小时内做完。

举证要三份，缺一份平台容易驳回：

1. **服务确实在听**：目标机 `ss -lntup | grep <端口>` 输出（证明不是自己没起服务）；
2. **映射确实配了**：面板端口映射截图（证明不是没放行）；
3. **外部确实打不通**：工作机 `curl -sv --noproxy '*'` 或 `nc -vz` 的完整输出，**至少三个不同端口**，最好隔 10 分钟再测一次（排除瞬时抖动）。

话术（英文工单）：

```
Hi, the instance <IP>:<SSH_PORT> is reachable for SSH, but the mapped TCP ports
<PORT1>, <PORT2>, <PORT3> are unreachable from outside (connection timed out).
I verified the services are listening on all three with `ss -lntup`, and the
port mappings are configured in the panel (screenshot attached). Tested twice,
20 minutes apart, from two different networks. Could you check whether inbound
traffic to those mapped ports is being filtered? If it can't be fixed, I'd like
to request a refund under the <N> day policy.
```

三类证据都留档到节点目录：`ip-quality.txt` 收 curl/nc 输出，截图命名 `<日期>-portmap.png`。

**退不了的情况**（超过窗口 / 平台只换不退）：把机器改成不依赖入站 TCP 的用途——只跑 hy2、当跳板到别的机器、或纯 DNS/DOH 前端。别为了「回本」继续在上面堆服务。
